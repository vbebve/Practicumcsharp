
Данный проект был разработан в рамках превого спринта учебной программы. Целями спринта были
1. Познакомиться с платформой ASP.NET Core
2. Научиться использовать базовые CRUD-операции
3. Научиться работать с DI
4. Тестировать приложение через SWAGGER

На текущем этапе в проекте реализованы следующие технологии: 

1. ASP.NET Core Web API
2. Dependency Injection (DI)
3. Swagger
4. DTO (Data Transfer Objects)

Список основных компонентов: 
1. Controllers — обработка HTTP-запросов и формирование HTTP-ответов.
2. DTOs — модели передачи данных между клиентом и API.
3. Interfaces — интерфейсы сервисов.
4. Models — внутренние модели данных приложения.
5. Realizations — реализации бизнес-логики.

Модель мероприятия имеет следующую форму :

ID - Уникальный идентификатор события. Присваивается автоматически. Тип данных - int
Title - Наименование события. Обязательное поле. Тип данных - string
Description - Описание события. Опциональное поле. Тип данных - string
StartAt - Дата и время начала события. Обязательное поле. Тип данных DateTime
EndAt - Дата и вермя окончания события. Обязательное поле, проходит валидацию относильное StartAt. Тип данных DateTime

API Endpoints: 
GET - /events - получение всех мероприятий
GET - /events/{id} - получение мероприятия по id
POST - /events - создание нового мероприятия
PUT - /events/{id} - изменение существующего мероприятия по id
DELETE - /events/{id} - удаление существующего мероприятия

Архитектура и обработка данных

Проект использует принцип разделения ответственности:

1. Контроллер принимает HTTP-запросы и преобразует DTO во внутренние модели.

2. Сервис выполняет бизнес-логику и управляет коллекцией мероприятий.

3. Интерфейс IEventService определяет контракт взаимодействия контроллера с сервисом.

4. Dependency Injection обеспечивает внедрение реализации сервиса.

На текущем этапе данные хранятся в оперативной памяти приложения с использованием List<Event>. После перезапуска приложения созданные мероприятия удаляются.

Запуск проекта

Требования:
1. Установленный .NET SDK версии 8.0 или выше.
2. Git (для клонирования репозитория).

Клонирование репозитория: 
git clone <repository-url>
cd Practicum

Сборка проекта 
dotnet build

Запуска приложения
dotnet run
